# Дизайн-спецификация панели Server Billing

**Статус:** утверждено владельцем, база для реализации и приёмки (t3). Палитра выбрана
владельцем: вариант **«Индиго»** (концепция C из `docs/design/palette-concepts.md`).
**Область:** только `src/public/{index.html,login.html,app.js,style.css}`. Бэкенд, API-контракт,
`src/index.ts`, `package.json`, продуктовая логика — вне области.
**Решения владельца (не обсуждаются):** только тёмная тема (без светлой палитры и без
переключателя), постоянный левый сайдбар (компоновка — по референсу infra-billing), верхний
header текущей панели убирается, сборки нет — только рукописные HTML/CSS/JS.
**Айдентика:** собственная, вариант «Индиго»: фиолетово-чёрные поверхности, ирис `#9C93FF`,
крупные мягкие радиусы, свет вместо рамок, деликатное свечение графика. Палитра, типографика,
формы и состояния — свои; из infra-billing взяты только пропорции оболочки и плотность таблиц,
ни один цвет оттуда не используется (см. §2.7).
**Что меняется по сравнению с текущей панелью:** тёмная тема сохраняется, но получает
собственную палитру и типографику вместо прежней; появляется оболочка с сайдбаром и три вида;
таблицы получают плотность и числовое выравнивание; добавляются состояния
(загрузка/пусто/ошибка/тост), подтверждение удаления и один inline-SVG график.
**Демо-данные:** только синтетические (см. Приложение А). IP — из диапазонов RFC 5737
(`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`). Реальная инфраструктура в репозиторий
не попадает — он публичный.

Сайдбар: `position: fixed; inset: 0 auto 0 0; width: 240px`, поверхность `--surface-2` (лёгкая
плашка светлее канвы: 1.12:1 — декоративно, см. §2.3), без разделительной линии.
Контент: `margin-left: 240px`, шапка `position: sticky; top: 0; height: 64px`.

### 1.2 Разделы и переключение видов

Переключение — **виды**, а не якоря: три независимых вида в одном `index.html`, активный вид
определяется `location.hash`, переключается обработчиком `hashchange` (~25 строк JS, без роутера
и сборки). Вид по умолчанию — `#/overview`; неизвестный hash → `#/overview`.

| Пункт сайдбара | hash | Что на виде | Данные |
|---|---|---|---|
| Обзор | `#/overview` | Сводка + KPI, график недель, «Требуют внимания» | `GET /api/dashboard` |
| Услуги | `#/services` | Таблица услуг + фильтры провайдер/тег, диалог тега | `dashboard.services`, `meta.providers` |
| Провайдеры | `#/providers` | Таблица аккаунтов + карточка «Добавить аккаунт» | `dashboard.accounts`, `meta.providers` |
| ● Синхр. / ● Ошибка / ● Выкл. | `#/providers?state=ok\|failed\|off` | Аккаунты, отфильтрованные по состоянию синка | `dashboard.accounts` |

Состояния пункта: покой — текст `--text`; hover — фон `--surface-3` (текст не меняется);
активный — плашка `--accent-soft` с внутренним контуром 1px `--active-line`, текст и иконка
`--accent`, вес 500, радиус 10px; focus-visible — ринг `--ring` с отступом 3px. Пункты — `<a href="#/…">` (работает middle-click и «открыть в новой вкладке»),
`aria-current="page"` на активном.

Группы навигации: «Обзор» стоит отдельным пунктом над группами (у него нет групповой подписи),
ниже — «Инфраструктура» (Услуги, Провайдеры) и «Синхронизация» (строки-счётчики со своими
точками статуса и числом аккаунтов).

Порядок видов в DOM: `#view-overview`, `#view-services`, `#view-providers` рядом, скрытые
`hidden`; рендер данных — один раз после `load()`, переключение только показывает нужный.
Каждый вид содержит свой `h1` (sr-only), заголовок в шапке дублируется визуально как хлебная
крошка.

### 1.4 Обоснование (один абзац)

Оболочка с сайдбаром требует активного пункта: если оставить одну длинную страницу с якорями,
сайдбар превращается в оглавление без состояния, а переход «Ошибка синхронизации → аккаунты,
у которых ошибка» становится невозможным — именно этот сценарий даёт группе «Синхронизация»
смысл. Три вида на хеше стоят ~25 строк ванильного JS, не требуют роутера, сборки и новых
API, сохраняют глубокие ссылки и кнопку «назад», и разводят две широкие таблицы (10 и 6 колонок)
с длинной формой, которые в одном вьюпорте конкурируют за ширину: на 1280 таблица услуг
занимает ~950px, и рядом с ней форма кредов уже не помещается. Внутри вида секции остаются
карточками — это тот же уровень группировки, что и в референсе компоновки, и он не мешает поставить форму
добавления аккаунта отдельной карточкой, а не модалкой: у шести полей и длинной подсказки
провайдера модалка на 480px тесна, а инлайн-форма переиспользует существующий `#add-account`
без переноса DOM.

## 2. Дизайн-токены

Все значения — CSS custom properties в `:root` файла `src/public/style.css`. Светлых значений
нет ни в одном токене. Токены — единственный источник цвета: в правилах компонентов не должно
быть hex-литералов.

**Решения по доступности и прозрачности (измерено в §2.3).**

- Полупрозрачные подложки бейджей (12–16 % цвета статуса поверх `--surface`) вынесены в
  отдельные токены `--badge-*-bg`: в правилах нет rgba-литералов, альфа зафиксирована и
  посчитана. Переносить эти токены на другой фон (например, на `--surface-2` в диалоге) без
  пересчёта контраста нельзя: значения 5.57–8.48:1 даны именно для `--surface`.
- `--text-dim #8D85AE` проходит 4.5:1 на `--bg/--surface/--surface-2` (5.13–5.73:1). На
  «авроре» сводки он даёт 4.38:1 — на верхнюю половину сводки `--text-dim` не ставить, там
  только `--text`/`--text-muted`. На `--surface-3` (4.77:1) и `--field` — тоже не используем,
  чтобы не зависеть от оттенка.
- `--text-faint #6A6190` — 3.32:1 на карточке, только нетекстовые элементы.
- Граница поля — `--border-strong #6B63A8` (3.34–3.54:1). Ослаблять её до `--border`
  (1.26:1 на `--field`) нельзя: граница — единственный носитель смысла «это поле».
- primary-кнопка: `--accent-ink` на `--accent` — 7.55:1; hover (фон `--text`) — 16.53:1.

### 3.4 Бейджи статуса и критичности срока

**Точка статуса (InkGlyph).** Один визуальный словарь на всё приложение: 12×12
`viewBox="0 0 12 12"`, круг r=3.5 залит текущим цветом; «нет данных» — полый круг r=3
(`fill:none; stroke-width:1.4`), «выключено» — полый пунктир (`stroke-dasharray="1.6 1.55"`),
«в процессе» — залитая точка цвета `--accent` с пульсацией 1.6s (статична при reduced-motion).
Тона: `ok` → `--ok`, `warn` → `--warn`, `failed` → `--danger`, `progress` → `--accent`,
`pending`/`off` → `--text-faint`. Размер 12px в тексте и таблицах, 8px — в плотных списках.
Точка декоративна (`aria-hidden`), если рядом есть слово; если она единственный носитель
смысла — `role="img"` и `aria-label` («покрыто балансом», «просрочено»). Цвет никогда не
единственный сигнал: рядом всегда слово или сумма.

```
статус:  ● активна          точка 8px + слово
срок:    через 3 д          фон badge-warn-bg, текст warn
оплата:  покрыто балансом   ok
синк:    ошибка             danger + точка
```

- Базовый бейдж: `display:inline-flex; align-items:center; gap:6px; height:22px;
  padding:0 8px; border-radius: var(--r-full); font-size:11px; line-height:1;
  white-space:nowrap;` — пилюля; точка-глиф наследует цвет текста
  (`.badge .glyph { color: currentColor }`).
- Фон бейджа полупрозрачный (12–16 % цвета статуса, отдельные токены), поэтому контраст
  считается по композиту над `--surface` (§2.3): `ok` → `--badge-ok-bg`/`--ok` (8.48:1);
  `warn` → `--badge-warn-bg`/`--warn` (8.92:1); `danger` → `--badge-danger-bg`/`--danger`
  (6.63:1); `accent` → `--badge-accent-bg`/`--accent` (5.57:1); `neutral` →
  `--badge-neutral-bg`/`--text-muted` (6.41:1). На `--surface-2` (диалог, тост) бейджи не
  используются; переносить подложки на другой фон без пересчёта нельзя.
- Статус услуги — точка + русское слово (данные в API остаются латиницей):
  `active`→«активна» (`ok`), `suspended`→«приостановлена» (`warn`), `deleted`→«удалена»
  (`danger`), `missing`→«не найдена» (`danger`), `unknown`→«неизвестно» (`neutral`).
- Статус аккаунта — синк-состояние: `ok` «синхронизировано», `failed` «ошибка», `off`
  «выключен», `never` «не синхронизировался». Приоритет вычисления: `!enabled` → off; иначе
  `lastError` → failed; иначе нет `lastSyncedAt` → never; иначе ok.
- Бейдж срока — см. §3.2. Бейдж не заменяет текст: слова обязательны.

## 5. Адаптивность

### 5.1 Пороги

| Ширина | Сайдбар | Шапка | Контент | Таблицы |
|---|---|---|---|---|
| 360–767 | drawer 280px, скрыт, `inert` | 2 строки (крошка + действия), гамбургер | gutter 16px | карточный список |
| 768–1023 | drawer 280px | 1 строка, гамбургер | gutter 24px | гориз. скролл `.table-wrap`, min-width |
| 1024–1279 | постоянный 240px | 1 строка, без гамбургера | gutter 24px | sticky header, max-height 62vh |
| 1280–1599 | постоянный 240px | 1 строка | gutter 32px, max 1440 | sticky header; таблица услуг — `min-width` по §3.3, при нехватке места скролл внутри `.table-wrap` (страница не скроллится) |

Пограничные правила: на `≥1024` у `body` / `.app-main` появляется `margin-left: var(--sidebar-w)`;
на `<1024` — `margin-left: 0`. `--gutter` меняется через media query (§2.2).

### 5.2 Сайдбар → drawer

- `<1024`: `.sidebar { transform: translateX(-100%); transition: transform 200ms var(--ease);
  z-index: 50; }`, `.sidebar[data-open="true"] { transform: none; box-shadow: var(--shadow-lg); }`;
  подложка `.scrim { position: fixed; inset: 0; background: var(--overlay); z-index: 40 }`.
- Открытие: кнопка `#drawer-btn` (иконка `menu`, 32×32, `aria-label="Открыть меню"`,
  `aria-expanded`, `aria-controls="nav"`). Закрытие: Esc, клик по scrim, клик по пункту
  навигации, ресайз ≥1024.
- Закрытый drawer получает атрибут `inert` (и `aria-hidden="true"`), чтобы Tab не уходил в
  скрытую навигацию; при открытом drawer `inert` ставится на `main` и шапку, фокус-трап —
  внутри `.sidebar`, возврат фокуса — на гамбургер.
- `body { overflow: hidden }` при открытом drawer (блокировка скролла страницы).
- На ≥1024 `inert`/`aria-hidden` снимаются, `#drawer-btn` скрыт (`display:none`), scrim не
  рендерится.

### 5.3 Таблицы: три стратегии

1. **≥1024 — sticky header + прокрутка внутри карточки.** `.table-wrap { overflow: auto;
   max-height: min(62vh, 620px) }`, `th { position: sticky; top: 0 }`. Заголовок карточки не
   скроллится. Полоса прокрутки — тонкая (`scrollbar-width: thin;
   scrollbar-color: var(--border-strong) transparent`).
2. **768–1023 — только горизонтальный скролл.** `max-height: none`, `.table-wrap {
   overflow-x: auto }`, таблица с `min-width: 960px` (услуги) / `760px` (аккаунты); у правого
   края — статичная подсказка-градиент `20px` (`linear-gradient(90deg, transparent,
   var(--surface))`) и `title` на контейнере «Прокрутите таблицу вбок».
3. **<768 — карточный список.** Один и тот же `<table>` перестраивается CSS:
   ```css
   @media (max-width: 767px) {
     .table-wrap { overflow: visible; }
     .table-card table, .table-card thead, .table-card tbody,
     .table-card tr, .table-card td, .table-card th { display: block; }
     .table-card thead { position: absolute; width: 1px; height: 1px; overflow: hidden; clip-path: inset(50%); }
     .table-card tr { border: 1px solid var(--border); border-radius: var(--r-lg);
                      padding: var(--s-3); margin-bottom: var(--s-2); background: var(--surface); }
     .table-card td { display: grid; grid-template-columns: 96px 1fr; gap: var(--s-3);
                      border: 0; padding: 3px 0; min-height: 0; text-align: left; }
     .table-card td::before { content: attr(data-label); color: var(--text-muted); font-size: 12px; }
     .table-card td[data-empty] { display: none; }
     .table-card td[data-actions] { grid-template-columns: 1fr; padding-top: var(--s-2); }
     .table-card td[data-actions]::before { display: none; }
     .table-card td[data-actions] .btn { width: 100%; }
   }
   ```
   Требования: в `app.js` каждой `<td>` ставится `data-label` (заголовок колонки), у таблиц —
   `role="table"`, у строк — `role="row"`, у ячеек — `role="cell"` / `role="columnheader"` (без
   этого `display: block` ломает семантику в части скринридеров). Ячейка действия помечается
   `data-actions`, занимает отдельную строку, кнопка — на всю ширину при высоте 40px. Пустые ячейки («—») в `app.js` получают `data-empty`
   и в карточной раскладке не занимают строку.
- Горизонтального скролла у `body` нет ни на одной ширине: это проверяется в чек-листе.

### 5.4 Сетки и плотность

- Карточки обзора: `display: grid; gap: var(--s-8)`. Блок KPI: `display:grid; gap:
  var(--s-4) var(--s-6); grid-template-columns: repeat(2, minmax(0, 1fr))` на `<640`,
  `repeat(4, minmax(0, 1fr))` на `≥640`; на 360 значения не переносятся (tabular, nowrap).
- Верх сводки: 2 колонки `≥1024`, 1 колонка ниже.
- Форма аккаунта: 2 колонки `≥768`, 1 колонка ниже.
- Тулбар: `≥768` — в одну строку с заголовком; `<768` — вторая строка шапки, селекты

- На 1600 ширина контента ограничена 1440px и центрируется (`margin-inline: auto`), чтобы
  строки таблиц не растягивались на 1600+; сайдбар остаётся 240px.

## 6. Доступность

1. **Контраст.** Все текстовые пары ≥4.5:1, крупный текст и UI-элементы ≥3:1 — измерено в §2.3,
   включая полупрозрачные подложки бейджей (по композиту) и текст на градиенте/«авроре» сводки.
   `--text-faint` не используется для текста; цвет никогда не является единственным носителем
   смысла (статусы — точка + слово, срок — бейдж + дата, ошибки — иконка + текст).
2. **Фокус.** Видимый фокус-ринг `2px solid var(--ring)` с `outline-offset: 3px` на всех
   интерактивных элементах; у полей — ещё и `box-shadow: 0 0 0 3px var(--ring-soft)`.
   `outline: none` без замены запрещён. Фокус не теряется при перерисовке таблиц (кнопка,
   открывшая диалог, получает фокус обратно).
3. **Клавиатура.** Skip-link «К основному содержимому» — первый Tab-элемент, ведёт на `#main`.
   Порядок: skip → навигация (пункты и группа синка) → logout → действия шапки → контент.
   Все действия доступны с клавиатуры: пункты меню — ссылки, `Sync`/`Тег`/`Удалить` — кнопки,
   `Enter`/`Space` работают нативно. Диалоги — нативный `<dialog>`:
   `Esc` закрывает, Tab зациклен, `aria-labelledby` на заголовок, фокус на первом поле.
   Drawer: `Esc`, фокус-трап, возврат фокуса, `inert` в закрытом состоянии.
4. **Семантика и подписи.** Один `h1` на вид (sr-only, заголовок дублируется в крошке),
   `h2` у карточек; ориентиры `header/nav[aria-label="Основная навигация"]/main/aside`;
   таблицы — `caption.sr-only`, `th scope="col"`; кнопки-иконки — `aria-label` («Выйти»,
   «Открыть меню», «Закрыть»); у полей — `<label>` (видимый), `autocomplete` для
   логина/пароля, `aria-describedby` для подсказки/ошибки, `aria-invalid`.
5. **Динамика.** `#toast` — `aria-live="polite"` (успех) / `role="alert"` (ошибка);
   `#app-error` — `role="alert"`; скелетон — `aria-hidden`, контейнер `aria-busy="true"`;
   live-region объявляет «Загрузка данных…» и «Данные обновлены». Фокус не перемещается
   автоматически при обновлении данных.
6. **Движение.** `prefers-reduced-motion: reduce` обнуляет анимации и переходы (§2.2),
   пульсация статуса и скелетона отключается, автоскролл — `auto`. Никакого мигания >3 раз/с.
7. **Масштаб.** На 200% зума нет горизонтального скролла страницы и обрезанного текста
   (кроме намеренного `truncate` с `title`); высоты — `min-height`, не фиксированные `height`
   у текстовых блоков.
8. **Язык.** `<html lang="ru">`; `lang="en"` не нужен (идентификаторы провайдеров — имена
   собственные, оставляем как есть).
9. **Формы.** Обязательные поля помечены `required`; ошибки — текстом, не только цветом;
   пароль — `type="password"`, кнопка показа пароля не требуется (нет в текущем UI); при
   ошибке сети форма не теряет введённые значения.

| 1 | Только тёмная тема: нет светлых токенов, `prefers-color-scheme`, переключателя темы | `grep -niE "light\|prefers-color-scheme\|theme-toggle" src/public/*` → пусто (кроме слова в комментарии); на странице нет контрола темы | P0 |

## 8. Границы реализации и запреты

- Меняются только `src/public/index.html`, `src/public/app.js`, `src/public/style.css`,
  `src/public/login.html` (+ этот документ). API, `src/index.ts`, `package.json`, адаптеры,
  схема БД — не трогаются.
- Новых запросов нет. Используются существующие: `GET /api/dashboard`, `GET /api/meta`,
  `POST /api/sync`, `POST /api/accounts`, `POST /api/accounts/:id/sync`,
  `DELETE /api/accounts/:id`, `PATCH /api/services/:id`, `POST /api/logout`,
  `POST /api/login`.
- Запрещено: React/Vue/Tailwind/shadcn, любая сборка, npm-зависимости, CDN, Google Fonts,
  внешние шрифты (`@font-face` с URL), иконки-спрайты из сети, canvas для графика, CSS-фреймворки,
  `!important` (кроме reduced-motion блока), inline-стили кроме вычисляемых высот/ширин
  (например, `style="height: …%"` у баров графика и `width` у meter).
- Бюджет CSS (`style.css`, без `login.html`): 600–900 строк. Ориентир: токены+база 130,
  каркас/сайдбар/шапка 150, карточки/KPI 90, таблицы 120, бейджи/аватары 70, кнопки/поля 100,
  диалоги/тосты/баннеры 90, график 30, адаптив 110 → ≈890.
- JS: без фреймворков, без классов-роутеров; hash-навигация — один обработчик; рендер — шаблонные
  строки с существующим `esc()`; никакого `innerHTML` из неэкранированных данных.
- Все демонстрационные данные и примеры в документации — синтетические (Приложение А).

## Приложение Б. Пересчёт контраста

Проверка любой пары из §2.3 (WCAG 2.1, sRGB). Запускать из корня репозитория:

```bash
python3 - <<'PY'
def lin(c):
    c /= 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4
def lum(h):
    h = h.lstrip('#')
    r, g, b = (int(h[i:i+2], 16) for i in (0, 2, 4))
    return 0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b)
def ratio(a, b):
    la, lb = sorted((lum(a), lum(b)), reverse=True)
    return (la + 0.05) / (lb + 0.05)
def comp(fg, alpha, bg):
    f = [int(fg.lstrip('#')[i:i+2], 16) for i in (0, 2, 4)]
    b = [int(bg.lstrip('#')[i:i+2], 16) for i in (0, 2, 4)]
    c = [round(alpha * x + (1 - alpha) * y) for x, y in zip(f, b)]
    return '#%02x%02x%02x' % tuple(c)
for fg, bg, need in [
    ('#ece9f9', '#0b0915', 4.5), ('#a9a2c9', '#121022', 4.5),
    ('#8d85ae', '#121022', 4.5), ('#6a6190', '#121022', 3.0),
    ('#9c93ff', '#121022', 4.5), ('#0b0915', '#9c93ff', 4.5),
    ('#77dcae', '#102a24', 4.5), ('#f3c978', '#322816', 4.5),
    ('#ff8e9a', '#351c25', 4.5), ('#b0a8ff', '#121022', 3.0),
    ('#6b63a8', '#15122a', 3.0),
]:
    r = ratio(fg, bg)
    print(f'{fg} on {bg}: {r:.2f}:1 ' + ('OK' if r >= need else 'FAIL'))
# полупрозрачные подложки бейджей: композит поверх --surface
for fg, alpha in [('#77dcae', .14), ('#f3c978', .14), ('#ff8e9a', .15), ('#9c93ff', .16), ('#a9a2c9', .12)]:
    bg = comp(fg, alpha, '#121022')
    r = ratio(fg, bg)
    print(f'{fg} on {alpha:.0%} over #121022 = {bg}: {r:.2f}:1 ' + ('OK' if r >= 4.5 else 'FAIL'))
PY
```

Ожидаемый вывод: `16.53`, `7.75`, `5.43`, `3.32`, `7.15`, `7.55`, `9.16`, `9.26`, `7.13`, `8.81`,
`3.45`; композиты бейджей — `8.48`, `8.92`, `6.63`, `5.57`, `6.41` — все OK.
